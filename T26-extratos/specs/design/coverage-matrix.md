# Matriz de cobertura — achados da crítica adversarial

Modo GENERATIVO (antídoto AP1): cada lente produz cenários de falha para cada módulo.
Nomes de módulo são os de `specs/technical/architecture.md`. Nomes de lente são os canônicos.

## Iteração 1 — V(1)

| id | module | lens | severity | description |
|------|--------|------|----------|-------------|
| ASM-01 | domain-model | Assumptions | 🔴 | `Dinheiro(Decimal,2)` assume escala fixa de 2 casas. OFX `TRNAMT` admite mais casas decimais; arredondar na entrada altera o valor e destrói a comparação exata que VAL-2 e a tolerância default zero dependem. Premissa não declarada em A1-A7. |
| ASM-02 | canonicalizer | Assumptions | 🔴 | O hash canônico assume que a descrição normalizada é ESTÁVEL entre importações da mesma fonte. Bancos alteram o texto entre exports (acrescentam nº de documento, mudam abreviatura); o hash muda, L2 falha e a duplicata de reimportação escapa — justamente o caso que L2 existe para pegar. Não declarado. |
| ASM-03 | dedup-engine | Assumptions | 🔴 | `classificar(nova, existentes)` não define o ESCOPO de `existentes`: mesma conta? todas as contas? qual janela temporal? Se restrito à conta, a duplicata cross-source entre contas distintas nunca é detectada (requisito da Fase 0). Se irrestrito, o custo explode. A arquitetura assume um escopo que nunca declarou. |
| ASM-04 | repository | Assumptions | 🔴 | UNIQUE sobre "a identidade" assume que identidade idêntica ⇒ duplicata. Para CSV sem ID nativo a identidade é o hash canônico — e duas transações realmente distintas com mesma data, valor e descrição (colisão legítima) produzem o MESMO hash. A constraint que garante I8 (idempotência) viola I6 (preservar colisão legítima). Contradição direta entre invariantes, no esquema do banco. |
| ASM-05 | ofx-adapter | Assumptions | 🟡 | Assume que `DTPOSTED` sem componente de fuso é irrelevante. Uma transação postada perto da meia-noite muda de dia conforme o fuso aplicado, deslocando-a de bloco de data e derrubando o casamento com a mesma transação vinda de outra fonte. |
| ASM-06 | reconcile-engine | Assumptions | 🟡 | Assume que existe no máximo um lançamento correspondente por transação (I4). A Fase 0 admite explicitamente que 1:N ocorre e deve virar pendência — mas o contrato `conciliar` não declara COMO o caso N é detectado antes de escolher o par 1:1. |
| ASM-07 | csv-adapter | Assumptions | 🟡 | Assume que o encoding declarado no perfil corresponde ao arquivo real. Export de banco brasileiro chega em cp1252 com BOM enquanto o perfil diz utf-8; a descrição vira mojibake, o hash canônico muda e a dedup de reimportação falha silenciosamente. |
| ASM-08 | fixture-generator | Assumptions | 🟢 | Assume que dados sintéticos reproduzem os desvios reais dos bancos. Se o gerador só produz arquivos conformes, VAL-1 e VAL-2 são verificados contra um mundo mais fácil que o real. |
| ARC-01 | cli | Architectural | 🔴 | `depends-on: todos`. O composition root concentra orquestração de 11 módulos sem contrato próprio: não é testável em isolamento e nenhum caso de uso é executável sem a CLI. Falta uma fronteira de aplicação entre a CLI e os engines — hoje o fluxo do UC-1 só existe dentro do parser de argumentos. |
| ARC-02 | matcher | Architectural | 🔴 | Um único módulo serve dois clientes com semânticas distintas: dedup compara transação × transação (mesma natureza, chave por identidade/valor) e reconcile compara transação × lançamento (naturezas diferentes, campos diferentes, pesos diferentes). O contrato `score(par) -> float` é genérico demais para estar correto nos dois — ou o módulo viola SRP, ou um dos dois usos vai receber um score sem significado. |
| ARC-03 | fixture-generator | Architectural | 🟡 | `fixture-generator` depende de `csv-adapter` — o gerador dos dados de teste depende do módulo que os dados de teste existem para testar. Um erro comum de interpretação de perfil se cancela nos dois lados e o teste passa com o defeito presente. |
| ARC-04 | reporter | Architectural | 🟡 | Depende de `repository` diretamente e lê o banco para montar o relatório. Não é testável sem banco, e a lógica de sub-rotulação de órfãos (esperado × anômalo) fica atrás de I/O. |
| ARC-05 | review-queue | Architectural | 🟡 | A camada L0 é consultada pelo `dedup-engine` via `repository.buscar_resolucao`, mas as resoluções são escritas pelo `review-queue`. Duas rotas para o mesmo dado, sem dono único: divergência entre o que a fila mostra e o que o motor aplica é invisível. |
| ARC-06 | canonicalizer | Architectural | 🟢 | `normalizar(bruto, perfil) -> Transacao\|Lancamento` devolve union. O normalizador passa a conhecer os dois tipos de destino; dois métodos com retorno único desacoplariam. |
| IMP-01 | reconcile-engine | Implementability | 🔴 | O contrato não especifica como resolver disputa: duas transações candidatas ao mesmo lançamento com scores próximos. Casamento 1:1 global é um problema de atribuição — guloso por score, guloso por data, ou ótimo (húngaro) dão resultados DIFERENTES. Sem essa decisão o módulo não é implementável de forma determinística, e determinismo é requisito (VAL-5). |
| IMP-02 | matcher | Implementability | 🔴 | `score(par) -> float` não especifica quais campos entram, com que peso, nem como campos ausentes (descrição vazia, contraparte nula) são tratados. Um implementador em sessão isolada inventará os pesos — AP7 no ponto mais crítico do sistema. |
| IMP-03 | csv-adapter | Implementability | 🟡 | `PerfilCSV` não tem esquema declarado: quais chaves existem, quais são obrigatórias, quais os tipos. `validar_perfil(p) -> [Erro]` é inimplementável sem esse esquema. |
| IMP-04 | repository | Implementability | 🟡 | `ResultadoImport` não tem forma declarada, mas o UC-1 exige que a CLI reporte novas / duplicatas-reimportação / duplicatas-cross-source / pendências. O contrato entre repository e cli está incompleto exatamente onde o caso de uso é verificado. |
| IMP-05 | fixture-generator | Implementability | 🟢 | `GroundTruth` sem formato declarado. Os testes da Fase 6 consomem essa estrutura para aferir VAL-1 e VAL-2. |
| SCI-01 | matcher | Scientific | 🔴 | duplica: IMP-02 — os pesos m/u de Fellegi-Sunter não têm valor nem método de estimação em `specs/technical/parametros-matching.md`. A FÓRMULA está referenciada (§2.1 de references), os PARÂMETROS não. Regra "não implementar algoritmo sem referência verificável" é violada no núcleo do dedup. |
| SCI-02 | matcher | Scientific | 🟡 | As faixas 95 / 85 / 70 (P3-P5) vêm de blog de fornecedor, não de literatura revisada por pares — a própria spec registra a ressalva e ainda assim adota como default. Nada no design prevê calibrar esses cortes contra o ground truth antes de usá-los para decidir fusão. |
| SCI-03 | reconcile-engine | Scientific | 🟡 | A janela de ±3 dias (P1) vem de um exemplo que a fonte declara "ilustrativo, não normativo". Não há evidência de que 3 dias corresponda à janela de compensação real do mercado brasileiro (D+0 PIX, D+1 TED, D+30 cartão). |
| SCI-04 | reporter | Scientific | 🟡 | A "janela de compensação" que separa órfão esperado de órfão anômalo não tem valor nem fonte em `specs/technical` — P1-P9 não a cobre. A sub-rotulação decidida na Fase 0 seria implementada com um número inventado. |
| SCI-05 | matcher | Scientific | 🟢 | A escolha entre Jaro-Winkler e Levenshtein normalizado (P6) segue em aberto, sem critério empírico definido para decidir — as duas se comportam de modo diferente em nomes de contraparte truncados. |
| SEC-01 | reporter | Security | 🔴 | Injeção de fórmula em CSV: descrição vinda do extrato começando com `=`, `+`, `-` ou `@` é exportada no relatório e executada quando o analista abre no Excel. O conteúdo vem de fonte externa não confiável (arquivo baixado ou recebido por e-mail) e o alvo é a máquina do operador financeiro. |
| SEC-02 | ofx-adapter | Security | 🔴 | OFXv2 é XML. Se o parser resolver entidades externas, um arquivo de extrato hostil executa XXE (exfiltração de arquivo local) ou expansão exponencial de entidades. O arquivo é entrada não confiável por definição — o adapter não declara desabilitar resolução de entidades. |
| SEC-03 | repository | Security | 🟡 | `listar(filtro)` sugere consulta dinâmica; nada no contrato obriga parametrização de SQL. Filtro montado por concatenação com texto vindo da CLI abre injeção na base financeira. |
| SEC-04 | cli | Security | 🟡 | Caminho de arquivo recebido do usuário sem validação (travessia de diretório na leitura, e escrita de relatório em caminho arbitrário). O arquivo SQLite é criado com permissão default — extrato bancário legível por qualquer usuário da máquina. |
| SEC-05 | fixture-generator | Security | 🟡 | O gerador escreve arquivos a partir de parâmetros; sem confinamento do diretório de saída, uma execução com caminho errado sobrescreve dados reais do analista. |
| SEC-06 | repository | Security | 🟢 | Sem criptografia em repouso: nomes de contraparte e histórico financeiro completo em SQLite texto claro no disco do analista. |
| PRF-01 | matcher | Performance | 🔴 | Bloco degenerado: milhares de tarifas de mesmo valor redondo (R$ 30,00) caem na mesma chave `(abs(valor), janela)`. Dentro do bloco a comparação volta a ser O(b²) — com b na casa dos milhares, o orçamento de 50k/60s estoura. Nem limite de tamanho de bloco nem estratégia de fallback estão declarados (premissa A4 sem mecanismo). |
| PRF-02 | dedup-engine | Performance | 🔴 | `classificar(nova, existentes)` é por transação e consulta o repositório a cada chamada: 50.000 idas ao banco para um lote de 50.000. Padrão N+1 no caminho crítico — a decisão de projeto que faz VAL-4 falhar antes de qualquer otimização de algoritmo. |
| PRF-03 | repository | Performance | 🟡 | Nenhum índice declarado além do UNIQUE de identidade. As consultas de candidato filtram por `(valor, data)` — sem índice composto, cada uma varre a tabela inteira, e a tabela cresce a cada mês. |
| PRF-04 | reconcile-engine | Performance | 🟡 | Se a resolução de IMP-01 for o casamento ótimo global (húngaro), o custo é O(n³) e inviabiliza VAL-4 mesmo com blocking. A escolha algorítmica em aberto tem consequência assintótica, não só de corretude. |
| PRF-05 | canonicalizer | Performance | 🟢 | Hash SHA-256 por transação a 50k é irrelevante no orçamento (registro explícito para impedir micro-otimização no lugar errado enquanto PRF-01 e PRF-02 seguem abertos). |
| REG-01 | repository | Regulatory | 🟡 | A conciliação alimenta escrituração contábil, sujeita a prazos legais de guarda, mas nenhum módulo tem requisito de retenção nem trilha imutável rastreado até ele. Nenhuma linha da arquitetura responde por essa obrigação. |
| REG-02 | repository | Regulatory | 🟡 | `NAME`/`MEMO` de extrato contêm dados pessoais de contrapartes (nomes de pessoas físicas em PIX). LGPD é aplicável e o design não declara base legal, política de retenção/eliminação, nem controle de acesso ao arquivo. |
| REG-03 | reporter | Regulatory | 🟢 | O relatório não registra versão do software nem os parâmetros efetivos da execução. Auditoria contábil exige reproduzir o número apresentado; sem isso o relatório não é reexecutável. |
| RES-01 | repository | Resilience | 🔴 | "Import atômico" é prometido sem declarar o limite transacional. Se o processo morre no meio de 50.000 inserções, o estado fica parcial — e a recuperação depende da idempotência, que por sua vez depende de a identidade já ter sido gravada. Sem transação por lote explícita, o mecanismo de recuperação depende do que a falha destruiu. |
| RES-02 | ofx-adapter | Resilience | 🟡 | `ofxtools` valida contra a especificação e lança exceção em arquivo não conforme. Sem política declarada de "linha ruim × arquivo ruim", uma única transação inválida aborta a importação inteira do lote. |
| RES-03 | csv-adapter | Resilience | 🟡 | Idem para linha com valor não parseável: sem quarentena de linhas rejeitadas, ou o lote inteiro se perde, ou as linhas somem silenciosamente — e o analista concilia sobre dados incompletos sem saber. |
| RES-04 | repository | Resilience | 🟡 | SQLite com outro processo segurando o lock devolve `database is locked`. Sem timeout nem política de retry declarados, uma segunda janela de terminal aberta derruba o import. |
| RES-05 | cli | Resilience | 🟢 | Sem tratamento declarado para disco cheio ao escrever o relatório de 50k linhas. |
| UX-01 | review-queue | UI/UX | 🔴 | O UC-5 exige que o analista resolva pendências, mas com dezenas de milhares de transações a fila terá centenas de itens e `listar(filtro)` não declara ordenação por impacto (valor), agrupamento por padrão recorrente, nem resolução em lote. A tarefa central do operador é inexecutável em tempo humano — o design escala o volume mas não a revisão. |
| UX-02 | cli | UI/UX | 🟡 | `import` não oferece `--dry-run`. Operação que altera estado financeiro e cujo desfazer é caro (resoluções persistidas) não tem prévia. |
| UX-03 | review-queue | UI/UX | 🟡 | `resolver(id, acao)` não tem desfazer. Por I7 a decisão humana é soberana e não sobrescrita — logo um erro de digitação do analista vira permanente por design. |
| UX-04 | reporter | UI/UX | 🟡 | `render(relatorio, formato)` não enumera os formatos suportados nem define o padrão. O relatório é o entregável que o analista consome; seu formato não está especificado. |
| UX-05 | cli | UI/UX | 🟢 | Nenhum requisito declarado de mensagens de erro não técnicas — mas a Fase 6 tem gate de teste manual que avalia exatamente "as mensagens são compreensíveis?". |
| SUS-01 | repository | Sustainability / Proportionality | 🟡 | Crescimento ilimitado sem política de retenção ou arquivamento. O conjunto `existentes` contra o qual o dedup compara cresce mês a mês, então o custo por importação cresce com a HISTÓRIA, não só com o tamanho do lote — o orçamento de 60s é medido num banco vazio e degrada indefinidamente em produção. |
| SUS-02 | matcher | Sustainability / Proportionality | 🟡 | O custo de similaridade é pago sobre candidatos acumulados de todos os períodos. Sem janela de comparação declarada, o trabalho gasto cresce sem que o valor entregue cresça: duplicata de reimportação de 3 anos atrás é praticamente impossível. |
| SUS-03 | fixture-generator | Sustainability / Proportionality | 🟢 | Regerar 50.000 transações a cada execução da suíte, em vez de materializar o dataset uma vez em `specs/datasets`, multiplica o custo do ciclo de teste sem ganho. |
| PRC-01 | reconcile-engine | Process / Workflow | 🔴 | `pendente-de-revisao` está declarado como estado TERMINAL (VAL-3 exige que todo item termine em exatamente um dos 5), mas é por natureza um estado de espera: o item muda de estado quando o humano decide. A máquina de estados não declara as transições permitidas, quem as dispara, nem o que acontece com um item pendente quando um novo `reconcile` roda. Estado órfão no sentido literal. |
| PRC-02 | review-queue | Process / Workflow | 🔴 | Um único tipo `Pendencia` e um único `resolver(id, acao)` cobrem dois processos diferentes: pendência de DEDUP (fundir ou não duas transações) e pendência de CONCILIAÇÃO (casar ou não transação com lançamento). As ações válidas divergem — "casar-manual" não faz sentido para dedup, "é a mesma transação" não faz sentido para conciliação. O contrato mistura dois fluxos. |
| PRC-03 | cli | Process / Workflow | 🟡 | Não existe passo de fechamento de período. O analista nunca declara "julho está conciliado", então órfãos rolam indefinidamente e nunca se distinguem de pendências novas — a diferença de tempo (40-60% dos não-casados) nunca se resolve por processo. |
| PRC-04 | cli | Process / Workflow | 🟡 | A ordem dos comandos não é imposta nem verificada. Rodar `reconcile` antes de importar o livro produz 100% de `orfao-no-extrato` — resultado indistinguível de uma falha real de conciliação, e o relatório não sinaliza que o livro está vazio. |
| PRC-05 | review-queue | Process / Workflow | 🟢 | Nenhum papel ou ator declarado para a resolução. Monousuário hoje, mas a autoria da decisão é justamente o dado que sobrevive ao ciclo. |
| GOV-01 | review-queue | Governance / Accountability | 🔴 | Nada declara trilha de auditoria append-only. I7 diz que a decisão humana não é sobrescrita por heurística — mas `resolver(id, acao)` pode ser chamado de novo e sobrescrever a decisão anterior sem deixar histórico. Não há como responder "quem decidiu fundir estas duas transações, quando, e com base em qual evidência" — que é exatamente a pergunta de uma auditoria contábil. |
| GOV-02 | dedup-engine | Governance / Accountability | 🟡 | `DecisaoDedup` carrega camada e evidência, mas nenhum contrato declara que isso é PERSISTIDO. Se a evidência vive só em memória, um falso positivo descoberto no fechamento seguinte é inauditável — e VAL-2 exige zero falso positivo, o que pressupõe poder investigar um. |
| GOV-03 | repository | Governance / Accountability | 🟡 | Nenhuma entidade tem proveniência declarada: a linha gravada não aponta para o arquivo e a fonte que a originaram. Com várias contas e vários exports, é impossível atribuir uma transação ao seu arquivo de origem para conferência. |
| GOV-04 | reporter | Governance / Accountability | 🟢 | duplica: REG-03 — o relatório não registra os parâmetros efetivos (limiar, janela, tolerância) daquela execução. |
| OBS-01 | cli | Observability / Operability | 🟡 | Nenhum módulo declara log estruturado. Quando o analista disser "esse valor está errado", não há registro de qual camada L0-L5 decidiu o quê — a única forma de diagnosticar é reexecutar, e a reexecução pode não reproduzir o estado da época. |
| OBS-02 | matcher | Observability / Operability | 🟡 | Nenhuma métrica de execução (pares avaliados, tamanho máximo de bloco, tempo por etapa). A degradação de PRF-01 se manifesta apenas como "ficou lento", sem nada que aponte o bloco degenerado como causa. |
| OBS-03 | cli | Observability / Operability | 🟡 | Sem códigos de saída diferenciados por classe de falha (arquivo inválido × banco travado × nada a fazer). Inviabiliza uso em script ou agendamento, e o próprio analista não distingue "rodou e não achou nada" de "falhou". |
| OBS-04 | repository | Observability / Operability | 🟢 | Sem comando de verificação de integridade da base (contagens por estado batendo com o total, casamentos órfãos apontando para linhas inexistentes). |
| CTL-01 | dedup-engine | Control Engineering | 🔴 | O laço de realimentação resolução-humana → L0 não fecha. A resolução é gravada para um PAR de identidades; se A1 for falsa e a mesma transação voltar com FITID novo, o par é diferente e a resolução não se aplica — a mesma pendência reaparece a cada importação, indefinidamente. O sistema reage ao evento mas não regula o estado: oscilação real, e o analista resolve o mesmo caso todo mês. |
| CTL-02 | matcher | Control Engineering | 🟡 | duplica: REG-03 — os limiares P3-P5 são configuração de runtime que altera o comportamento de classificação, e nada registra qual valor vigorou em cada execução. Alterar o limiar reclassifica silenciosamente o histórico já processado: deriva de estado sem sinal de erro. |
| CTL-03 | dedup-engine | Control Engineering | 🟡 | Não existe caminho de correção: uma transação marcada como duplicata por engano não tem operação de des-duplicação. O sistema tem malha de decisão, mas nenhuma malha de correção do próprio estado. |
| LIN-01 | csv-adapter | Linguistics / Grammar | 🔴 | `PerfilCSV` é uma mini-linguagem declarativa sem gramática especificada. "Convenção de sinal" admite pelo menos duas leituras corretas — "débito vem negativo no campo valor" ou "existe uma coluna que indica o sinal" — e duas implementações fiéis ao contrato produzem sinais opostos para o mesmo arquivo. Ambiguidade de protocolo com consequência de sinal invertido em dinheiro. |
| LIN-02 | domain-model | Linguistics / Grammar | 🟡 | `EstadoConciliacao` mistura eixos: `casado`, `casado-com-divergencia`, `orfao-no-extrato` e `orfao-no-livro` são RESULTADOS, `pendente-de-revisao` é FASE DO PROCESSO. Um vocabulário não ortogonal no enum força perguntas mal formadas ("está casado ou pendente?"). |
| LIN-03 | matcher | Linguistics / Grammar | 🟡 | `score(par) -> float` não declara escala nem direção: 0-1 ou 0-100, maior é mais parecido ou é distância. Os parâmetros P3-P5 falam em 95/85/70. Um implementador que devolva distância normalizada 0-1 satisfaz o contrato e inverte todas as decisões de fusão. |
| LIN-04 | canonicalizer | Linguistics / Grammar | 🟡 | "Descrição normalizada" não tem regra especificada: caixa, acentos, pontuação, espaços múltiplos, abreviaturas. Duas implementações corretas do contrato geram hashes canônicos diferentes para a mesma transação, e L2 deixa de funcionar entre versões do próprio sistema. |
| LIN-05 | domain-model | Linguistics / Grammar | 🟢 | Nomes de domínio em português (`Transacao`, `Lancamento`) e nomes de módulo em inglês (`dedup-engine`, `review-queue`) no mesmo contrato. A linguagem ubíqua do DDD fica bilíngue na fronteira. |
| MEC-01 | ofx-adapter | Mechanical Engineering | 🟡 | Versão de `ofxtools` não fixada. A biblioteca valida contra a especificação e REJEITA arquivos não conformes — uma atualização mais estrita passa a recusar extratos de banco que antes importavam. Tolerância zero disfarçada de robustez. |
| MEC-02 | csv-adapter | Mechanical Engineering | 🟡 | O perfil casa colunas por nome ou posição exata. O banco acrescenta uma coluna ou muda o rótulo do cabeçalho e a importação quebra por inteiro, em vez de degradar com aviso. Nenhuma folga declarada para a variação que o próprio problema (layouts heterogêneos) garante que vai ocorrer. |
| MEC-03 | repository | Mechanical Engineering | 🟡 | Sem versionamento de esquema nem caminho de migração. Qualquer mudança de tabela em um ciclo seguinte torna ilegível a base do mês anterior — e a base é o registro contábil acumulado, não um cache descartável. |
| MEC-04 | matcher | Mechanical Engineering | 🟢 | duplica: CTL-02 — atualização de `rapidfuzz` altera sutilmente os scores, reclassificando silenciosamente casos de fronteira já decididos. |

## Iteração 2 — V(3)

Nota de rastreabilidade: `V(3)` é o carimbo do contador do engine (que conta transições de fase);
corresponde à seção **`# V(2)`** de `specs/technical/architecture.md` (que conta versões de
arquitetura). Os achados abaixo são contra essa seção.

| id | module | lens | severity | description |
|------|--------|------|----------|-------------|
| ASM-09 | store | Assumptions | 🔴 | `IdentidadeObservacao(fonte, arquivo_hash, indice_linha)` assume que reimportar significa reimportar o MESMO arquivo. O UC-2 é reimportação com janelas SOBREPOSTAS: arquivo diferente, hash diferente, índice diferente — logo identidade de observação nova, e o UNIQUE não impede nada. A correção de R1 comprou a saída da contradição I6↔I8 ao preço de reduzir a idempotência de VAL-5 ao caso do arquivo byte-idêntico; o caso real do UC-2 caiu inteiro no dedup probabilístico. |
| ASM-10 | domain-model | Assumptions | 🔴 | `ChaveEvento` inclui `descricao_normalizada`, e a correção de CTL-01 (chavear L0 por evento para sobreviver à troca de FITID) depende de essa chave ser estável. ASM-02 já estabeleceu que a descrição NÃO é estável entre exports do mesmo banco. A correção herda exatamente a fragilidade da qual pretendia escapar. |
| ASM-11 | domain-model | Assumptions | 🟡 | `Dinheiro(valor, escala)` passou a guardar a escala original, mas nada declara que a igualdade é pelo valor numérico e não pela representação. `1250.00` vindo do CSV e `1250.000` vindo do OFX seriam o mesmo evento e comparariam desiguais. |
